# Bundled image decode: isolated Chromium acceptance lane

Status: implemented and statically checked; browser runtime NOT run locally and CI result pending. No native/device/airplane-mode or full application acceptance claim.

The fixture imports the actual extensionless chapter image and story media resolvers and actual generated manifests. The build asserts both canonical TypeScript resolver modules are included. Only the Supabase transport import is replaced by a throwing sentinel; no resolver/media-cache mock is used. JavaScript fetch and CacheStorage access also throw and count violations. Browser Image requests are distinct from fetch API calls and intentionally use local HTTP.

The builder disables config/env/public discovery and copies only referenced assets, rejecting invalid/traversal/encoded paths and symlinks. Current reviewed counts are 637 chapter plus 1,785 story images, exactly 2,422 files. Their measured total size is **158,578,892 bytes**; the earlier approximately 164 MiB folder estimate included unreferenced assets and filesystem accounting. Generated manifests must retain these counts or the lane fails for review. No content, source resolver, production assets, credentials or deployment is modified.

A fresh Chromium context serves only generated code and these files from an exact loopback origin. Unexpected origins/paths/query strings fail the run; WebSockets are denied and service workers blocked. Each resolver must return its exact bundled path before Image.decode succeeds with nonzero natural dimensions. Four concurrent workers release image sources after decoding. Every asset must be requested and all 2,422 must pass. Malformed bytes and a missing local path must both reject Image.decode with EncodingError (timeouts do not count); the runner additionally checks malformed HTTP 200 with exact synthetic bytes and missing HTTP 404. Per-image wait is 15 seconds, fixture total admission deadline 10 minutes, outer renderer wait 11 minutes, workflow deadline 20 minutes. These bounds cause failure rather than silently skipping an asset; arbitrary browser/process stalls remain subject to the workflow limit.

The artifact is JSON only: full-success counts, negative-control count, maximum decoded dimensions, exact referenced bytes, browser version, elapsed time and unexpected-request/page-error/failed-request counts, all required zero. An explicit empty data-URL favicon suppresses implicit favicon network requests; there is no general failure whitelist. No image copies, secrets, profile data or raw network logs are uploaded. The browser remains online to reach local HTTP; this does not simulate Capacitor airplane mode, clean Android packaging, editorial correctness, artwork provenance or UI layout.

Static evidence: three builder guard tests PASS; actual bundle/copy PASS (2,422 files and bytes above); Python AST and workflow syntax checked. Actual decode counts/dimensions and runtime are deliberately pending CI. Official pinned Playwright 1.62.0 uses the existing CI provisioning pattern. This new branch-only lane does not modify the native, guest or previous acceptance lanes.
