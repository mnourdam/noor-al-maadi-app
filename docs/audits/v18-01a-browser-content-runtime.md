# Browser content runtime acceptance (verified browser-only)

This selected-module fixture is not the whole application UI, login flow or native build. This lane builds actual controller, snapshot generator/validator/storage, local-first store and Supabase SDK/client modules with no target-module mocks. Build environment-file loading is disabled and the client URL/key are explicitly synthetic loopback-only values. A separate loopback HTTP server supplies synthetic public content; the browser has a fresh temporary persistent profile, no real auth session, and no production data. Only generated assets are served, never the profile directory.

The executed checks used native Chromium IndexedDB and real HTTP response streaming: hold an incomplete first encyclopedia page until the controller times out, retry a roughly 15 MB synthetic content refresh, verify complete durable content and subsequent ordinary HTTP without restart, identify the held GET and require its browser `requestfailed` event with `ERR_ABORTED` before retry, release the retired stream, simulate CDP freeze/resume, verify offline local/IDB reads, then close/reopen the browser with the same profile and origin. Page requests outside that exact origin are blocked and fail acceptance; service workers and WebSockets are blocked. This is browser context request isolation, not a claim of whole-machine firewall enforcement.

Local execution is blocked before page creation: installed Chromium 156.0.8078.79 fails `process_singleton_posix.cc:297`, `socket() failed: Operation not permitted`, then SIGABRT. The fresh-profile/about:blank probe establishes an environment restriction, not a stale profile or application defect. No security bypass was attempted. Local bundle build, both positive/counterfactual bundles, five build-target guard tests and Python syntax validation passed. Actual browser runtime acceptance subsequently passed in the dedicated CI environment described below; the local restriction was not bypassed.

The dedicated repair-branch workflow installs official Playwright 1.62.0 and its Chromium, uses Node 24/locked npm dependencies, and uploads only sanitized result JSON. No APK packaging, signing, deployment, live backend or credentials are used. CDP lifecycle simulation is not Android background/force-stop/device acceptance. Orderly persistent-profile reopening is not crash or OS force-stop durability. Synthetic HTTP content and anonymous SDK configuration do not establish Supabase JWT/RLS acceptance or full app UI correctness.

The positive lane must observe cancellation of the exact held GET, not merely completion of the server's tail write. A separate temporary-build counterfactual replaces exactly one query-signal-forwarding return with `return query`, preserving controller timeout behavior. It must reach the timeout with the held response still pending and fail to observe transport cancellation; unrelated launch/build errors are not accepted as negative-control success. No production source is edited. The synthetic `/health` check proves ordinary local HTTP works afterward, not that the user's production API or full app connectivity is repaired. Reopening loads the fixture assets online before reading durable content; offline reads are a separate explicit step, not offline navigation-shell acceptance.

The coordinator downloaded and verified the archive; this independent review reconciled the saved evidence with the reviewed harness assertions, rather than independently downloading the archive again.

The positive result is `PASS_BROWSER_ONLY` on **Chrome/151.0.7922.34**, with eight assertion groups, zero observed external page requests and zero page errors:

1. Actual local store hydrates the synthetic baseline.
2. The identified partially streamed GET emits `requestfailed` with `ERR_ABORTED` before retry.
3. The timed-out refresh returns false, releases the controller and preserves baseline durable version 1.
4. A same-runtime retry succeeds and stores updated content with 1,500 encyclopedia rows and a checksum.
5. Releasing the retired stream leaves that durable result unchanged; a subsequent synthetic health fetch succeeds without restarting the browser.
6. CDP freeze/resume preserves readable local content.
7. Explicit browser offline mode rejects a health fetch while IndexedDB and local reads remain available.
8. Orderly browser close/reopen at the same origin and profile preserves the durable result and hydrates the updated local content.

These are eight grouped checks, not eight independent end-to-end scenarios. The separate counterfactual result is `EXPECTED_MISSING_TRANSPORT_ABORT`: removing only query-signal forwarding in the temporary negative bundle still reaches the normal controller timeout, but the identified held GET emits no failure event during the three-second observation window. The server stream remains unreleased and the controller is no longer applying. This supports the transport-cancellation regression boundary; it does not claim indefinite absence of cancellation. Positive application modules remain unmodified.

**Acceptance scope:** actual selected-module browser streaming/cancellation, retry, IndexedDB/local-store reads, and orderly profile persistence under this synthetic fixture. Android lifecycle, OS force-stop/crash durability, full application UI, production connectivity, real hosted Supabase permissions and whole-machine network containment remain untested by this lane. Reopen serves the fixture shell online; it is not offline cold-start or PWA asset-cache acceptance. No deployment or production activation follows from this PASS.
