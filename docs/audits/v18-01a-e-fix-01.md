# V18-01A / E-FIX-01 — Dead-Letter and real identity partition

Scope: P1-01 only. Base: `0819e2a435237655e2fb9a54302eadfc9a786e7a`, branch `v18-01a-outbox-recovery`.
The overall Phase E decision remains **HOLD**. No release or Android acceptance is implied.

## Cause and change

`Storage.key()` enumerates physical keys, including `::owner=...`; the old archive compared them to logical keys from `keyFor`. Reading after the first archive therefore threw `dead-letter-key-mismatch`.

`src/lib/offline/dead-letter.ts` now captures the archive's Storage object, owner and identity epoch before awaiting a lock. In a partitioned runtime it uses explicit physical keys throughout legacy reads, copies, confirmation, enumeration and clear. It filters foreign physical namespaces before reading their values, then verifies the full expected physical key and the letter/source snapshot. It fails closed for a foreign requested user or a changed identity.

The existing partition marker `Storage.prototype.__originalGetItem` is inspected read-only to recognize the installed adapter. No production code changes Storage.prototype or the identity partition. Unpartitioned legacy runtimes retain the existing shared archive behavior and its strict validation. The application already installs the real partition at startup; the new acceptance suite exercises that implementation, not a simulated mapper.

Storage names, key serialization, old physical owner-suffixed entries, V17 arrays without revisions, Web Lock names, revision matching and the archive-before-remove order are preserved. In a mixed V17 array, only the current owner's snapshots are migrated or cleared; other users' snapshots remain untouched in that array. This fix does not guess how to reassign historical foreign snapshots to another account.

An archive receipt now identifies the actual physical entry in partitioned runtimes. No production caller consumes this key as a logical key. `archiveRejected` still calls `remove(snapshot.id, snapshot)` only after the archive write/read-back is confirmed; a newer revision remains queued.

## Acceptance and historical comparison

New suite: `tests/offline/outbox-dead-letter-partition.test.ts`.

```sh
./node_modules/.bin/vitest run --config vitest.outbox.config.ts tests/offline/outbox-dead-letter-partition.test.ts --reporter=verbose
```

**21/21 passed** using real `installIdentityPartition`, jsdom storage, fake IndexedDB and a fake Web Lock service. Server access and fetch are forbidden/mocked. It covers:

- Two consecutive archives and reading both.
- Closing IDB handles, resetting modules, reinstalling the real partition and reading after restart.
- Alice/Bob switching, clear for one account, explicit foreign-user requests rejected before any namespace access, and malformed Bob entries not blocking Alice.
- V17 revisionless migration, preserving foreign legacy snapshots, and reading pre-fix physical entry formats with and without source/revision.
- Quota, silent writes, failed confirmation reads, archive capacity 500, corrupt data, wrong keys/owners and mismatched source snapshots; original Outbox work is retained.
- Archive confirmation before conditional dequeue, stale revisions, interrupted dequeue and restart, partial migration failure and restart.
- Identity changes while waiting for the archive lock or during archive write confirmation.

Before the implementation, the initial 18 acceptance cases had **11 failures / 7 passes**. Three further edge cases were then added, yielding the final 21-case suite. These counts describe different suite revisions and are not a claim of 21 baseline failures.

The historical R1 was run unchanged:

```sh
./node_modules/.bin/vitest run --config docs/audits/repros/v18-01a-phase-e/vitest.config.mjs -t '\[R1\]'
```

Before the fix, it passed by observing the bug. After the fix, it fails its historical `toThrow("dead-letter-key-mismatch")` assertion because listing no longer throws. This expected failure is not an acceptance failure; the historical assertions and Phase E audit artifacts remain unchanged. Run them at the audited SHA to reproduce the original bug.

P1-02 through P1-07 are outside this change. In particular, this does not fix generic Outbox fallback/identity races (P1-03), late enqueue ordering, pending gameplay grants or reward recovery. Owner fencing here is local to Dead-Letter; conditional dequeue still delegates to the existing Outbox API. Web Locks are still required for archive mutation, and unreadable own-account archives still fail closed rather than being treated as empty. Real Android/device validation and the pre-existing hydration issue remain pending.
