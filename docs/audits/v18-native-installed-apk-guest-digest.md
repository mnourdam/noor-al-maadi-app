This establishes the transfer-stage blocker, not its underlying performance cause.

AOSP's official [shell utility inventory](https://android.googlesource.com/platform/system/core/+/show/master/shell_and_utilities/README.md), Android 15/API35 section (retrieved blob c7c622ec7da73974883d61359984965a279fe0ae), lists sha256sum among Toybox utilities. The [Toybox implementation](https://android.googlesource.com/platform/external/toybox/+/40d21c59f76a9388b0ebb5c4c706732c2d034a67/toys/lsb/md5sum.c) documents SHA256 output and hash-plus-filename formatting. That immutable implementation reference is not an attestation of the emulator image's exact Toybox build; actual availability and successful output remain runtime requirements.

The shared digest helper now requests `/system/bin/toybox sha256sum` on the exact path returned by pm. It accepts only `/data/app/` plus one or two nonempty shell-inert ASCII segments, each at most 255 characters, then `base.apk`. No dot/parent segment, empty segment, whitespace, shell substitution/operator, quoting, wildcard or arbitrary path is accepted. This is strict syntactic canonicality of the Package Manager path, not independent filesystem symlink attestation. Unknown install layouts fail closed rather than widening the shell boundary.

The result must be exactly one 64-hex digest, one or two ASCII separating spaces, and that exact filename. No warnings, multiple records, extra fields or alternate paths are accepted. Command nonzero/unavailable, timeout, malformed output and mismatched expected APK hash all fail before launch. Normal install, exploratory install, reconciliation and the legacy verification method share this helper. The existing 30-second hash cap and remaining-budget caps are unchanged; there is no transfer fallback, skip, repeated install or reconciliation-to-success promotion. The expected digest remains the previously verified exact APK receipt digest. Neither path nor raw tool output is emitted in retained evidence.

Offline tests cover modern two-directory paths, one-directory fixtures, shell/segment negatives, precise output framing, unavailable/timeout, remaining-budget expiration and mismatch blocking verified installation. Existing receipt tests adapt their hash-operation mocks without changing stage/error assertions. 108 Python controls pass; independent review CLEAR with 108/108 controls independently rerun. No claim of installed-app, Home or feature acceptance until actual runtime verification.
