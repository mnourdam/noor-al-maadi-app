# Shared notification realtime identity lifetime

Local actual-module reproduction on `11dd2f9` failed both new regressions: a stable subscriber still received two retired Alice callbacks after Bob became active, and delayed Alice `getUser` completion installed Alice channels after the owner change. This is a channel-lifetime/callback defect, not evidence of a data disclosure or a hosted RLS failure. HUD and Notification Center effects can remain mounted; the banner's own owner-scoped resubscription does not force the shared reference count to zero.

The bounded correction in `src/lib/notifications/server.ts` observes owner changes only while subscribers exist. Every channel admission captures owner/epoch, requires matching SDK user, and owns its own retired flag/channels. Old callbacks check current identity before each listener, including synchronous identity changes during notification. Teardown detaches before SDK removal and cannot clear a successor; pending authentication cannot install after final release. Guest/mismatched/error authentication admits no channels. Existing channel filters and shared reference counting remain. No list/cache/UI changes, added refetch, permission changes, reconnect loop or hosted calls.

Actual module and identity are tested with SDK channel/auth mocks: initial two failures now pass; stable switch, delayed auth, ABA, per-listener retirement, multiple subscribers/final release, guest/error/mismatch/rejection, and synchronous subscribe retirement are covered. Existing notification list-flight/banner identity regressions remain complementary. These are local lifecycle controls, not real Realtime delivery, full auth-provider or browser/Android acceptance. Existing offline early-return behavior is deliberately unchanged, and mounted Center rows/HUD count retirement is a separate concern not fixed or accepted here.
