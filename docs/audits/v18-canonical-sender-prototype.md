# Dormant canonical owner-sender prototype

Scope: one noninternal image from the issue's reporter only. Staff canonical sending is explicitly unsupported because the current model uses one owner identity for uploader and recipient; this slice does not silently redefine it. Legacy default three-image and staff/internal paths remain unchanged. Text-only replies continue through the existing reply API; the owner-only restriction applies to this new image-sending protocol, not a blanket prohibition on staff text replies. The actual composer has a closed explicit protocol selector, visible one-image limit, unsupported-role picker denial and pending retry state. Current product callers still omit canonical protocol and the production picker flag remains OFF. Only the synthetic browser build explicitly enables its picker.

The actual sender uses actor credentials only: immutable draft/message/image/body/issue/digest/size binding → proposed actor reserve RPC → exact fixed quarantine upload → actor finalize. Successful upload acknowledges only the client request, not trusted terminality. A409 or other uncertain upload error cannot mark uploaded or finalize. A subsequent trusted ready reservation may bypass retransmission only after server attestation. Pending throws a distinct error, retains the exact draft, disables mutation, and never calls onSent or clears the message. Explicit same-draft retry can publish once. Owner/epoch, thread, protocol and staff-mode transitions remount the composer and fence stale callbacks; owner notifications clear drafts without relying on a parent render.

Disposable SQL alone implements the proposed actor APIs. It checks actual synthetic feedback issue reporter ownership, rejects staff/other actors, serializes immutable request binding, privately chooses decoder revision and attempt token, and creates input intent before upload. No token/revision authority is returned to the client. Ready/finalize require the exact reservation/attempt relationship, generation, owner, issue, internal scope and digest. Changed request fields and cross-reservation same-generation collisions reject. Actor endpoints never mark writer terminal, call the decoder, or gain service authority. Finalization delegates only to the existing attested publication function and is idempotent for the exact message.

The existing74-record baseline keeps its original buckets. The later prototype uses intended fixed feedback-images-quarantine/canonical buckets. The browser test selects a synthetic PNG through actual product preparation, submits the actual composer and observes pending with unchanged text and zero onSent. Outside the client, the test controller observes the completed upload and exact service bytes/digest/size, supplies the explicitly testbench-only terminal evidence, and runs the actual service worker. The same UI retry publishes and refreshes the actual canonical viewer, which must visibly decode the exact worker output. A second upload is forbidden by the test. Native checks also require strict403/42501 other-owner/staff reserve and finalize denial, changed payload denial, exact replay and one unchanged publication.

This does not establish a deployed actor API, production worker scheduling/lease/in-flight proof, full retention drain, staff canonical sending, full authentication-provider orchestration, full app or Android acceptance. Browser network interception continues to disable ordinary HTTP caching. Existing pixel/retirement evidence is separate from this new sender slice until its native runtime is verified.
