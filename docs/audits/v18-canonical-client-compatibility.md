# Inactive canonical-v1 client compatibility

This isolated branch adds a closed `legacy | canonical-v1` selector to the actual `FeedbackImages` component. All existing callers remain legacy; picker flags and production policies/migrations are unchanged. Descriptor content cannot opt itself in. Unknown protocols are filtered. Canonical mode uses a fixed `feedback-images-canonical` bucket, strict version/message/attempt/key/JPEG/size/SHA descriptor, actual actor SDK download, and owner/session/epoch checks across download and digest verification. Digest equality is not authorization or trusted decoding. The component retains local-URL lifecycle guards and includes protocol plus the entire validated immutable canonical descriptor in remount identity.

The existing 74-record disposable baseline continues using its original fixture buckets. Only the later publication prototype creates the intended v1 canonical bucket and writes its actual worker output there. Its SELECT policy and new actor-derived descriptor RPC require current accepted publication and authenticated owner/staff/internal authority. No service token is supplied to the Node client. The Node client uses the actual app contract module and real Supabase SDK against the verified loopback API, with bounded response bodies, per-request cancellation, fixed routes, scrubbed child environment and outer process deadline. Its returned descriptor remains test-process memory, not the sanitized artifact.

Planned native assertions include owner/staff canonical bytes, other-owner/internal descriptor denial, and stale descriptor rejection after retirement. Retired acceptance requires a recognized actual Storage denial, not just any thrown error. Unpublished descriptor is absent; actors cannot write the new canonical bucket. Server-side current publication controls remain necessary even for a previously issued valid descriptor.

Local component tests use actual component/adapter/identity with SDK transport mocked. They prove exact Blob delivery to the local URL, invalid descriptor/MIME/size/digest rejection, old default behavior, owner/ABA retirement and descriptor/protocol replacement. JSDOM does not decode or paint image pixels. These are complementary boundaries: native SDK/worker wire evidence (pending execution) plus actual-component DOM behavior, not a full browser end-to-end, Android, deployed client or release acceptance. No compatibility alias rewrites canonical keys into legacy paths.
